# SCCD-X Engine v2.00

A qualitative structural engine for world politics. It takes `sccd` v1.00 —
**Sovereign-Civilian Capacity Dynamics** (Vi Nhật Sơn, Parts I–V) — and plugs
two forcing blocks into the two terms that v1.00 left exogenous.

## What it does

`sccd` v1.00 models a state as ten capacity components and leaves two terms of
its own ODE system purely exogenous:

```
dS₃/dt = **S₃_natural**    − ρ_b(1−λ/λmax)² − ζ·C₅^ψ·(S₃−S₃floor)
dC₅/dt = **C₅_structural** + ε_p·C₅(1−C₅)·RevPol + η·C₅²·C₃ + ξ·Ĉ₄Ĉ₁(1−C₅)
```

Those two starred terms are the engine's largest hole. They set the drift of
the two variables that control the whole non-linear core — S₃ drives λ, which
multiplies *all* of S; C₅ is the C denominator *and* the (1−C₅) factor in Ψ —
and v1.00 has nothing to say about either.

v2.00 fills them from two further papers by the same author:

| Block | Paper | Timescale | Tag |
|---|---|---|---|
| **D** | *The Wheel of Fate: From the Ancient "Prosperity Trap" to the Modern Fertility Crisis* | demographic | `DEGROW` |
| **A** | *The Displacement Hypothesis*, 2nd ed. | AI adoption | `DISPL` |

Both papers ship with the repository: [`docs/Degrow.pdf`](docs/Degrow.pdf) and
[`docs/The_Displacement_Hypothesis_v2.pdf`](docs/The_Displacement_Hypothesis_v2.pdf).

Block D is a **router**, not another pressure. A quantity of adjustment
pressure is generated by load; what the paper varies is *which channel carries
it*, and the split variable is the availability of voluntary instruments:

```
violent_share = (1 − d₃)^route_sharpness
```

## Two languages, genuinely separate

The page has a `VI` / `EN` tab pair. Press `VI` and everything is Vietnamese —
chrome, loop details, gate meanings, calibration warnings, the narrative, the
whole provenance tab. Press `EN` and everything is English.

There is no bilingual mode and no half-translated state. This is enforced, not
promised:

- 406 templates must have both sides, or `validate2.py` fails
- 160 UI strings must have both sides
- a missing i18n key **raises** rather than silently falling back to English
- `web/index.html` must contain **zero** Vietnamese characters — the page is a
  renderer and every string arrives from the API
- switching language **re-runs the diagnosis** server-side rather than
  translating in the browser

The numeric results are asserted identical across languages: same trajectory,
same fragility verdict.

## Quick start

```bash
git clone https://github.com/vinhatson/sccdx-engine.git
cd sccdx-engine
pip install numpy

python serve.py                    # the web UI at http://127.0.0.1:8777
python validate2.py                # 119 structural checks
python validate_v1.py              # the v1 inconsistency report
python sea2027/run.py --lang en    # the eleven ASEAN polities
```

Python 3.9+. `numpy` is the only hard requirement.

### The HTTP API

`serve.py` is the primary server and needs nothing but `numpy`.

```bash
curl http://127.0.0.1:8777/api/v2/health
curl "http://127.0.0.1:8777/api/v2/presets?lang=en"
curl "http://127.0.0.1:8777/api/v2/schema?lang=en"
curl "http://127.0.0.1:8777/api/v2/events?lang=vi"
curl "http://127.0.0.1:8777/api/v2/audit?lang=en"

curl -X POST http://127.0.0.1:8777/api/v2/diagnose \
     -H "Content-Type: application/json" -d '{"lang":"en"}'
```

Every reference endpoint takes `?lang=vi|en`. `POST /api/v2/diagnose` returns
the verdict, capacity, forcing, loops, bifurcation, attractor, trajectory,
horizon verdict, uncertainty and fragility.

Run [`api_fastapi.py`](api_fastapi.py) instead if you want OpenAPI docs and an
ASGI app — that one needs `fastapi` and `uvicorn`.

## The 2027 ASEAN run

[`sea2027/`](sea2027/) is a complete worked application: all eleven ASEAN
polities through the engine, data retrieved 2026-10-09.

```bash
python sea2027/run.py                                 # Vietnamese
python sea2027/run.py --lang en --json out.json       # English + full dump
python sea2027/make_pdf.py                            # 22 technical PDFs
python sea2027/make_prose_pdf.py                      # 22 prose PDFs
```

It ships 44 pre-built PDFs in two sets, and **the difference between them
matters**:

- [`sea2027/pdf/`](sea2027/pdf/) — the **instrument's output**: tables,
  per-component provenance tags, OAT rows, gate projections, the trajectory.
  5–6 pages each, 11 polities × 2 languages.
- [`sea2027/pdf_prose/`](sea2027/pdf_prose/) — the **argument about what that
  output means**. 2 pages each, ~20,000 words across the 22, with a strip of
  figures at the top so every claim can be checked against the run that
  produced it.

The split is the same discipline the engine keeps internally: **the engine
emits codes and never a sentence**, and prose lives in one place where it can be
audited. `prose_en.py` and `prose_vi.py` are INTERPRETATION and say so on every
document. The Vietnamese prose is *written*, not translated.

## Honest limits — read this first

This is the part to read before quoting any number from this engine.

**The v2 outputs are ORDINAL. They are a ranking and a threshold-crossing map,
not a level.** The engine says so itself at the end of every validation run:

```
36 of 83 v1 parameters carry a value from the source paper; 46 do not.
ALL 46 v2 parameters are ANALYST or DERIVED2 — the two new papers are
qualitative and state no coefficients.
```

That is not a disclaimer bolted on afterwards; it is why every derived field
carries a provenance tag you can inspect, and why `python validate_v1.py`
exists to print the v1 model's own inconsistencies rather than quietly
patching them. Four of them are `CRITICAL`, and the engine **reproduces them
faithfully** rather than fixing them silently:

- **INC-7** — in `dC₅/dt` all three endogenous terms are positive and there is
  no depolarisation term, so C₅ rises monotonically toward 1 for every
  trajectory, hence Ψ → 0 regardless of scenario.
- **INC-8** — in `dS₃/dt` both endogenous terms are negative, so S₃ can only
  decay and the model cannot generate the legitimacy reconstitution that Part V
  documents for 1980–86.
- **INC-9** — Part IV §2.1 writes a `dC₁/dt` equation, but §7.1 omits C₁ from
  the state vector. With C₁ exogenous there is no closed feedback loop in the
  non-linear system at all. (`simulate(..., c1_dynamic=True)` promotes it.)

`validate2.py` reports these as `KNOWN-DEFECT`, not as failures: they record
that the engine faithfully reproduces a defect `sccd.spec.KNOWN_INCONSISTENCIES`
already documents. A `KNOWN-DEFECT` count of 4 is the expected, correct result.

**On the ASEAN run specifically:** `judgment.py` is an explicit ANALYST overlay
— one block per polity, every number argued in place. It is a judgment, it is
labelled as a judgment, and you should disagree with it in the open rather than
treating it as measurement.

## Solver

`numpy` alone is enough, but Part IV §8.1 of the source paper mandates an
adaptive **stiff** solver (LSODA / Radau / BDF). Without `scipy` the engine
falls back to the explicit DP45 in [`sccdx/integrate.py`](sccdx/integrate.py)
and **reports that it did so** — in `trajectory.solver` and in the returned
notes.

DP45 is not a stiff solver. It tracks this system to ~1e-6 at the coefficient
magnitudes in `spec`/`spec2`, but install `scipy` before raising any rate by an
order of magnitude or adding sub-year shock pulses:

```bash
pip install scipy
```

`/api/v2/health` tells you which backend is live (`"ode_backend": "scipy"`).

## Repository layout

```
sccd/          v1.00 — the ten components, the ODE core, the loops, the spec
sccdx/         v2.00 — the two forcing blocks, events, presets, i18n, narrative
web/index.html the renderer; holds no prose of its own
serve.py       the primary server, stdlib + numpy only
api_fastapi.py the optional ASGI alternative, with OpenAPI docs
validate2.py   119 checks across both versions and both languages
validate_v1.py the v1 inconsistency report — prints what the paper got wrong
validate_lang.py  the language-parity checks (imported by validate2.py)
sea2027/       the eleven ASEAN polities, 44 PDFs, the analyst overlay
docs/          the three source papers, design notes, the validation log
```

`validate_lang.py` is a module, not an entry point — running it directly prints
nothing and exits 0. `validate2.py` calls its checks, and that is where you
will see them.

## Contributing

Issues and pull requests are welcome. What would help most:

1. **Calibration.** 46 of 83 v1 parameters and all 46 v2 parameters carry no
   value from any source paper. A defensible value for even one, with a cited
   basis, upgrades a whole branch of output from ordinal to cardinal.
2. **Argument with the analyst overlay.** `sea2027/judgment.py` states its
   reasoning per polity so it can be contradicted. Contradict it in an issue.
3. **Resolving the v1 inconsistencies.** `validate_v1.py` names each one and
   proposes a fix. Implementing one behind a flag, with a test, is a clean
   contribution.

Keep `python validate2.py` at 119 PASS / 0 FAIL, and keep both language sides
populated — the test suite will fail you otherwise.
